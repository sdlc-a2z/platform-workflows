# R0-WS2-009 — shared service CI

## What this story built

`service-ci.yml` and `service-image.yml` in a **public** `platform-workflows` repository,
with `platform-lib-go`, `platform-contracts` and the service template calling them, and
`sdlc-docs` given CI for the first time.

A caller is 18 lines.

## Why this repository is public

GitHub shares reusable workflows from a private repository only with organisations on Team
or Enterprise Cloud. `sdlc-a2z` is on Free, so every call failed at startup with no jobs
and no log — including a three-line probe, which is what isolated the cause. The API even
accepts `actions/permissions/access = organization` on a Free organisation and does
nothing, which is why it looked like a workflow bug for three attempts.

Split into its own repository rather than making `platform-infra` public: that one will
hold Terraform — project identifiers, VPC layout, subnets, node pools — and for a platform
whose security design is built on network zones (HLD §10.2), that is reconnaissance
material. Workflow files are build instructions.

Hardened before publishing: secrets are referenced by name only, with values injected at
run time from the calling private repository; the image registry became a required input
so nothing here names infrastructure; the Postgres credentials are for a container that
lives one job on the runner's loopback, and say so.

## Why the image job is a separate workflow

GitHub validates every job's `permissions` in a called workflow against the caller —
**including a job whose `if` will skip it**. With the image job inside `service-ci.yml`,
`platform-lib-go` — a library, `push-image: false` — still had to grant `id-token: write`
merely for the workflow to start. Splitting is what keeps least privilege possible: a
library calls `service-ci.yml` and grants nothing.

## What the gates are, and what each one already caught

- **Coverage at 80%** — `R0-WS2-002` shipped at 61.5% with its whole interceptor chain
  untested.
- **`govulncheck`** — GO-2026-6443, a remotely triggerable gRPC server panic, was in the
  first version pinned by a library seventeen services import.
- **An unprivileged Postgres role** — a superuser bypasses RLS, so a tenancy suite run as
  one passes while proving nothing.
- **`CI: true`** — the tenancy suites `t.Fatal` rather than skip, so the guarantee cannot
  go untested behind a green build.
- **`actionlint`** — added because this story lost three pushes to a workflow that would
  not parse. `platform-contracts` carried an invalid one for weeks, undetected, because no
  repository had a remote.

## What could not be built, and why

**The cross-repository registry check.** It checked the dependency graph from every
repository. A called workflow's `GITHUB_TOKEN` reaches only the repository that called it,
and `sdlc-docs` is private. Minting a personal access token with read access to every
private repository and inheriting it into a *public* workflow is a security decision, not
a workaround — so the check moved into `sdlc-docs`' own CI, which did not exist until now
and runs it on push and on a weekday schedule.

**The generated repository's compile test, in CI.** Same limit: the template's CI cannot
check out the private `platform-lib-go` that a generated service's `replace` directive
points at. CI checks the layout contract and substitution; `make test` locally checks that
it compiles. The workflow emits a warning rather than passing quietly. It closes when
`R0-WS2-008` publishes the module.

**`skills.py --check` and `specs.py --check` in `sdlc-docs`' CI.** Both need the sibling
repositories on disk. Same reason, same honesty: recorded in the workflow.

Three separate consequences of one fact — a workflow token cannot read a private sibling.
Worth stating plainly, because the fourth time it appears it should be recognised rather
than debugged again.

## Definition of Done

Met, except two rows:

- **Deployed** — no cluster (`DEVELOPMENT.md` §3, backstopped by `R0-ALL-003`).
- **"An unsigned image is rejected by the cluster admission policy"**, this story's own
  acceptance criterion, needs Binary Authorization and therefore `R0-WS1-002`. The
  `image` job is written and has never run: there is no Artifact Registry to push to.
  Carried to `R0-ALL-003`.

The other two criteria are met: a service repository consumes the workflow in 18 lines,
and neither existing repository still carries a hand-written build job.
