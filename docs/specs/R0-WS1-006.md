# R0-WS1-006 — Terraform in CI

## What this story built

`terraform.yml`: plan on a pull request with the result posted as a comment, apply on
merge to `main`. Called by `platform-infra`, and exercised twice end to end — the
network in this project was applied by it, not by anyone's laptop.

## The properties that make it worth having

**Apply uses the saved plan.** Re-planning at apply time applies something nobody reviewed;
the pull request approved *that* set of actions.

**`-detailed-exitcode`.** 0 no changes, 1 error, 2 changes — so apply runs only on 2, and
drift is visible. A plan that always exits 0 says nothing about whether the world still
matches the code.

**Federated authentication, no key.** A service-account JSON in a secret never expires and
can be read by any step that runs after it, which is what HLD §10.3 forbids. The token here
lives minutes and is bound to one repository by the provider's `attribute_condition`.

**`environment:` maps to a GitHub environment**, so `prod` can require a reviewer before
apply starts while `dev` runs straight through.

## Split into two workflows, for a reason worth knowing

Building and signing the image is `service-image.yml`, not a job here. GitHub validates
every job's `permissions` in a called workflow against the caller — **including a job
whose `if` will skip it**. With the image job inside, `platform-lib-go` — a library,
`push-image: false` — still had to grant `id-token: write` merely for the workflow to
start, and every call failed at startup with no jobs and no log.

## What it cost to get here

Eight failures, and only two were this workflow's own bugs. The rest were GitHub behaviours
that report as something else, all now written into the `ci-workflow-review` skill:

- A reusable workflow in a private repository needs Team or Enterprise. The API accepts
  `access_level = organization` on a Free plan and it does nothing.
- `actions/checkout` persists its token as an `extraheader`, overriding a
  `url.insteadOf` rewrite — so the credential you configured silently loses.
- `x-access-token` is a GitHub App username; with a PAT, a *clone* is refused as "Write
  access to repository not granted".
- `GITHUB_TOKEN` reaches only its own repository. Hit three times in this platform before
  anyone wrote it down.

The lesson that stuck: **ask the provider who you are and what you can reach, before asking
it to do the thing.** One API call ended four rounds of guessing, and that step is permanent.

## What is not here

**`service-image.yml` has never run.** There is no Artifact Registry to push to and no
Binary Authorization to reject an unsigned image, so its half of the gate is written and
unproven — `R0-WS2-009`'s carried criterion, at `R0-ALL-003`.

**No credential for modules.** `platform-terraform-modules` is public, so
`terraform init` fetches it with nothing. Three attempts at a narrow credential each
closed off, and at that point the credential cost more than the privacy bought.
